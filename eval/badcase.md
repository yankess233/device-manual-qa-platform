# Badcase 记录

> 用法：每次跑完 `run_eval.py`，从 `per_query.jsonl` 里挑出没命中的题，按下面模板补一条。
> 记录的重点不是"指标多高"，而是"知道它为什么错、改了什么、同类错误还剩多少"。
> 目标：P0 阶段至少填满 10 条，且**归因要落到具体文件/函数**。

## 归因分层

| 层级 | 典型症状 | 对应代码 |
| --- | --- | --- |
| L1 解析 | PDF 里的表格/公式没进 Markdown，图片摘要错位 | `import_process/nodes/pdf_to_md.py`、`md_img.py` |
| L2 切分 | 答案被切断、标题污染、短章节被合并吃掉 | `import_process/nodes/ducment_split.py` |
| L3 召回 | gold 不在 top-k、稀疏/稠密单路失效、过滤过严 | `vector_search.py`、`milvus_util.py` |
| L4 融合/精排 | gold 召回但排名掉到 k 之外、断崖把相关文档截掉 | `rrf.py`、`rerank.py` |
| L5 生成 | 检索对但答案错、编造参数、不弃答 | `answer_output.py`、`prompt/` |

## 已确认问题（待逐条填证据）

### BC-01 · 索引内容编码损坏

- **现象**：Milvus 集合 `kb_chunks_v1` 的 `content` 全是替换字符（`\ufffd`），`item_name` 存着 `{"item_name": "..."}` 整段 JSON。
- **证据**：`eval/corpus.py` 的 `build_from_milvus()` 直接抛"编码损坏"；`eval/.cache/_corpus_dump.txt` 对比同一份 `_new.md` 是正常 UTF-8。
- **归因层级**：L1（导入链路写库前编码错）+ B5（LLM 返回 JSON 未解析）
- **影响**：只要用旧集合检索，召回质量与指标全部失真；评测必须先重建语料。
- **修复动作**：（待办）在 `import_milvus_node` 写库前做编码断言；`item_name_recognition` 解析 JSON 后再入库。
- **复测**：（待填）

### BC-02 · 「操作指导」空切片

- **现象**：切分后存在 `## 操作指导` 这种 11 字的空壳切片（c009），它是二级标题但正文全是三级标题。
- **影响**：占用召回名额、污染上下文；`min_content_length=500` 的合并策略没覆盖到它。
- **归因层级**：L2
- **修复动作**：（待办）合并时跳过"纯标题、无正文"的 section，或把它作为 `parent_title` 而不是独立切片。
- **复测**：（待填）

### BC-03 · 表格被拆成两片（规格）

- **现象**：`## 规格（1/3）` + `## 规格` 两片，同一张表被切开；`2000kΩ`、`9V/1.5V 电池` 落在第二片。
- **影响**：问"2000kΩ 档精确度"时若只召回第一片，答案缺失；Recall 天然封顶。
- **归因层级**：L2
- **修复动作**：（待办）表格整体不切分，或切分后给子片补表头（列名）。
- **复测**：（待填）

### BC-04 · 参数型问题召不回「技术指标说明」（F01）

- **题目**：RS-12 的显示屏是几位数？
- **gold**：`c007`（`## 技术指标说明`）
- **实际 top-5**：`c014 交流电压测量` / `c015 直流电流测量` / `c003 控制与端口` / `c016 电阻测量` / `c000 封面`
- **症状**：gold 完全没进 top-5（A4 精排后仍未命中）
- **归因层级**：L3 召回（切片粒度问题，不是模型问题）
- **根因**：`技术指标说明` 是一整段 457 字的**单行**文本，同时包含显示位数、二极管电流、蜂鸣阈值、
  电池规格、输入阻抗、频宽、温度、湿度、海拔、重量、尺寸、认证等十余个互不相关的指标。
  稠密向量被平均成"万用表说明书"的泛化语义；而"显示屏"这个词在电压/电流测量章节里反复出现，
  于是那些章节反而更"像"问题。
- **修复动作**：把该段按"指标名: 值"拆成独立切片（`显示位数: 3 ½ 数位/2000 位`），或在导入侧
  额外抽一层结构化参数表。属于 P1 改造，未在 P0 动手。
- **复测**：待 P1。预期 F01 / F03 / M08 三题回到 top-1，`fact` 类 Hit@5 从 0.917 → 1.0。

### BC-05 · 「尺寸」被面板布局抢走（M08）

- **题目**：尺寸是多少？（上文问过"这台表多重"）
- **gold**：`c007`（技术指标说明）
- **实际 top-5**：`c003 控制与端口` / `c000 封面` / `c015 直流电流测量` / `c014 交流电压测量` / `c002 安全标识`
- **症状**：未命中
- **归因层级**：L3 召回
- **根因**：与 BC-04 同源（大杂烩切片）。额外一层：`c003 控制与端口` 里全是"面板布局/部件标识"，
  与"尺寸"在语义空间里近邻；封面 `c000` 有整机外形描述，也近邻。
- **修复动作**：同 BC-04；另可在 `item_name` 之外增加 `section_type`（参数/步骤/安全）作为标量过滤，
  让参数型问题只在参数切片里检索。
- **复测**：待 P1。

### BC-06 · 「电池型号」被电池测试章节抢走（F03）

- **题目**：仪表使用什么型号的电池？
- **gold**：`c007`（技术指标说明，里面有 `一粒9V (NEDA 1604) 电池`）
- **实际 top-5**：`c019 电池测试`（rank 1）/ `c004 功能符号指示` / `c002 安全标识` / `c007`（rank 4）
- **症状**：召回但排名第 4，勉强进 top-5；换成 top-3 就丢
- **归因层级**：L3 召回 + L4 融合
- **根因**：稀疏通道把"电池"这个高频词权重拉高，`电池测试` 章节标题直接命中；而 gold 里
  "电池"只出现一次。这暴露了"标题参与稀疏打分"的副作用：**章节标题词会系统性压过正文答案**。
- **修复动作**：待验证——把 `title` 从稀疏嵌入文本里剥离（只对 `content` 做稀疏），
  或在 RRF 里给"标题命中"降权。这正是 A3 之后要继续做的第 6 组实验。
- **复测**：待 P1，指标看 `table` / `fact` 两类的 MRR。

### BC-07 · HyDE + RRF 整体负收益（配置级）

- **现象**：A2（混合）→ A3（+HyDE+RRF）：Hit@5 0.900 → 0.875，MRR 0.756 → 0.714，
  nDCG 0.792 → 0.754，且每题多一次 LLM 调用（冷启动实测 **2871 ms/题**）。
- **证据**：`eval/results/baseline-v4/summary.md`、`per_query.jsonl` 逐题对比。
- **归因层级**：L3 召回污染 + L4 融合
- **根因**：本场景的答案几乎都是"参数/步骤/阈值"这类**事实型**内容，HyDE 生成的是
  "看似专业的说明文"，会把不存在的数值（例如凭印象写出的量程）带进检索空间；
  RRF 只按名次融合、不看分数绝对值，等于给这份"编出来的文档"和真实问题同样的投票权。
- **修复动作**：生产默认关闭 HyDE，保留 `HYDE_ENABLED` 开关；若要保留，改成"仅当 query
  不含型号/数值时启用"的条件路由。
- **复测**：关闭后线上应回到 A2 的检索质量，同时省掉 2.9 s/题的 LLM 延迟。

### BC-11 商品名被写成 JSON 串，问答永远在反问"你指哪款产品"

- **现象**：导入后 `kb_chunks_v1.item_name` 的值是 `{"item_name": "RS PRO RS-12 数字万用表"}`
  （带换行和花括号），`kb_item_names_v1` 里也是同样的串。问「RS-12 怎么测电阻？」时
  系统回答"我不确定您指的是哪款产品"，并把 JSON 原样念出来。
- **归因（L1 解析层）**：`item_name_recognition_node` 把 LLM 输出直接当商品名用，
  而 qwen3.8-flash 有时返回 JSON 对象而不是纯文本。JSON 串被写进 Milvus 标量字段，
  再回填到每个 chunk，既污染展示又破坏模糊匹配。
- **修复动作**：新增 `knowledge/utils/text_normalize.py::normalize_item_name`，
  兼容 JSON / 代码围栏 / 带引号字符串，取 `item_name|name|model` 等字段；
  识别节点入库前统一归一化，空结果降级用文件名。配套 12 个单测。
- **复测**：清空两个集合并重新导入后，`item_name` 为纯文本 `RS PRO RS-12 数字万用表`，
  「电池怎么换？」能正常给出 840 字带引用的答案。
- **仍未解决**：即便商品名干净，「RS-12 怎么测电阻？」仍会进入"请确认产品"分支——
  查询与商品名的向量相似度低于 0.6 的中置信阈值。建议加一条**型号精确匹配短路**
  （query 中出现与 item_name 相同的型号 token 时直接确认），而不是盲目下调阈值。
