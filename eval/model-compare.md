# 模型切换实测：qwen-flash → qwen3.8-flash

> 时间：2026-11-12；同一天、同一份语料、同一套 50 题、同一张 3060。
> 复现：`python -m eval.run_eval --run-id <id>` + `python -m eval.answer_ab --models ...`

## 1. 怎么保证"可比"

换模型最容易跑出假结论，所以先做了三件事：

1. **HyDE 缓存键加入模型名**（原来只有 `query + item_names`）。
   不改这里的话，换模型后会直接命中旧模型生成的假设文档，
   两张表会一模一样——看起来"换模型没影响"，实际是缓存把模型差异吃掉了。
2. **A1/A2 当对照组**：纯稠密/混合检索都不调用 LLM，换模型后必须**完全一致**。
   三组 run 的 A1/A2 指标逐位相同，说明语料、题目、缓存都没串。
3. **思考模式单独作为变量**：qwen3.8-flash 默认开思考，
   所以跑了「默认」和「`enable_thinking=false`」两遍，否则分不清是模型差异还是模式差异。

## 2. 检索层：几乎没有区别

| 配置 | 指标 | qwen-flash | qwen3.8-flash（默认思考） | qwen3.8-flash（关思考） |
| --- | --- | --- | --- | --- |
| A1 稠密 | Hit@5 / MRR | 0.875 / 0.758 | 0.875 / 0.758 | 0.875 / 0.758 |
| A2 +稀疏 | Hit@5 / MRR | 0.900 / 0.756 | 0.900 / 0.756 | 0.900 / 0.756 |
| A3 +HyDE&RRF | Hit@5 / MRR | 0.850 / 0.725 | 0.850 / 0.729 | 0.875 / 0.728 |
| A4 +精排 | Hit@5 / MRR | 0.950 / 0.885 | 0.950 / 0.885 | 0.950 / 0.885 |
| A5 +断崖截断 | Hit@5 / MRR | 0.950 / 0.885 | 0.950 / 0.885 | 0.950 / 0.885 |

**读法**：

- A1/A2/A4/A5 完全一致 —— 检索质量由「切分 + 向量 + 精排」决定，跟 LLM 无关，
  换模型不会把 Hit@5 从 0.95 变成 0.98，**想涨点只能改切分和融合**。
- A3 的 ±0.025（1 道题）是**生成方差**：同一模型、同一个 prompt、temperature=0，
  MoE 模型仍会有细微措辞差异，翻转一道题就是 2.5 个百分点。
  **50 题规模下，单题翻转不构成"变好/变差"的证据。**

## 3. 真正的差异：HyDE 延迟

| 模型 + 模式 | p50 | p95 | 平均 | 最大 |
| --- | --- | --- | --- | --- |
| qwen-flash | 2.9 s | 3.7 s | 3.0 s | 6.8 s |
| qwen3.8-flash（默认思考） | **16.0 s** | **47.6 s** | **22.0 s** | 72.4 s |
| qwen3.8-flash（关思考） | 5.2 s | 6.6 s | 5.2 s | 10.2 s |

（每格 50 次冷启动调用的实测值，含网络往返。）

结论：**默认思考模式下，HyDE 会让首字延迟从 3 秒涨到 22 秒**，在线问答直接不可用。
关掉思考后是 5.2 秒，仍然比 qwen-flash 慢 1.8 倍。

## 4. 答案层：8 题人工可比对（`eval/answer_ab.py`）

固定同一份检索上下文（混合 + 精排 top-6），只换模型，用生产同一份 `ANSWER_PROMPT`。

| 模型 | 平均延迟 | 平均 tokens | 弃答正确（2 题） |
| --- | --- | --- | --- |
| qwen-flash | 1.7 s | 2953 | 1 / 2 |
| qwen3.8-flash（默认思考） | 10.0 s | 3280 | 2 / 2 |
| qwen3.8-flash（关思考） | 2.8 s | 2820 | 2 / 2 |

个案（本地复跑后生成 `eval/results/answer_ab_*/answers.md`）：

- **N02「电池仓盖有几颗螺丝」**：qwen-flash 答"有一颗螺丝"——**纯编的**。
  qwen3.8 两个模式都回答"文档只提到用螺丝/螺母固定，未给出数量，无法确认"。这是本轮最有价值的一个差异。
- **O01「支持蓝牙吗」**：三者都正确弃答（初版脚本因词表缺"未明确说明"把两个正确答案判成硬答，
  已修正并 `--rescore`，这也是"自动判分不可靠"的活证据）。
- **P02「测电阻前的安全准备」**：qwen3.8（思考）会把量程上限 250Vrms/15s 一并补上，更完整；
  但耗时 42.9 s。
- **风格差异**：关思考版本会输出 `[文档1][文档2]` 形式的引用标记——这是生产 Prompt 里没有要求的，
  属于"模型自带的引用习惯"，对做溯源反而是加分项。

## 5. 结论与建议

1. **换模型不会改善检索**，这个项目的瓶颈在切分（参数型问题召不回）和融合（标题词压过正文），
   不在 LLM 选型。指望换模型救指标是方向性错误。
2. **qwen3.8-flash 默认思考模式不适合在线问答**：HyDE 22 s、答案 10 s（p95 更差）。
   要用就**必须**配 `LLM_ENABLE_THINKING=false`（已在 `.env` / `.env.example` 落好，
   `AIClients` 里读这个开关下发 `enable_thinking`）。
3. **关思考后值得换**：答案质量不低于 qwen-flash（弃答 2/2 vs 1/2），
   延迟 2.8 s vs 1.7 s（可接受），还自带引用标记。**代价是 1.6 倍延迟，收益是少编答案。**
4. **真正该修的是弃答机制**：N02 上 qwen-flash 硬答、qwen3.8 也只是"嘴上说无法确认"，
   流程里没有任何"上下文无依据就必须拒答"的强约束。换模型解决不了，得在 Prompt + 后处理上做。

## 6. 复现命令

```bash
# 旧模型
LLM_DEFAULT_MODEL=qwen-flash python -m eval.run_eval --run-id model-qwen-flash
# 新模型（默认思考）
LLM_DEFAULT_MODEL=qwen3.8-flash python -m eval.run_eval --run-id model-qwen38-flash
# 新模型（关思考）
LLM_DEFAULT_MODEL=qwen3.8-flash LLM_ENABLE_THINKING=false python -m eval.run_eval --run-id model-qwen38-nothink
# 对比
python -m eval.compare_runs eval/results/model-qwen-flash eval/results/model-qwen38-nothink
# 答案层 A/B
python -m eval.answer_ab --models "qwen-flash,qwen3.8-flash,qwen3.8-flash:nothink"
```

## 7. 这次实测踩到的坑（写下来防止下次再踩）

| 坑 | 症状 | 修法 |
| --- | --- | --- |
| 缓存键不含模型名 | 换模型后指标完全不变 | 把 `model` 和 `thinking` 拼进 HyDE 缓存键 |
| 没区分思考模式 | 延迟/质量混在一起，说不清是谁的锅 | 加 `LLM_ENABLE_THINKING` 开关，单独跑一组 |
| 首调 CUDA 预热 | 第一组配置 P95 虚高 | 跑测前 warm_up |
| 弃答词表太窄 | 正确答案被判"硬答" | `--rescore` 重判，词表补"未明确/无法确认/没有提及" |
| 关键词匹配太脆 | "断开被测电路电源"不含"断开电源"→漏判 | 关键词只作辅助，最终人工 0/1 |
